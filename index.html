Approach

01

Start with the problem

Technology is a means, not an end. Every project begins with understanding what needs to exist and why — then choosing the simplest tools that get it there.

02

Ship early, learn fast

A working prototype in someone's hands teaches more than a month of planning. I build incrementally, test with real users, and iterate based on what actually happens.

03

Sweat the details

The difference between software that works and software that feels good lives in the margins. Loading states, transitions, error messages — I care about those things.
